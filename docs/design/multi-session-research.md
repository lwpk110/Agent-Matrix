# 多会话体验调研与设计建议

调研日期：2026-10-18。范围：公开官方文档、官方页面内的界面示例；未进入需要登录的产品工作区。以下区分已核实的产品能力与 Agent Matrix 的设计建议。

## 结论

采用「会话总览 → 会话摘要与回合 → 单轮 Runtime 链路 → 节点详情」四层结构。主要借鉴 LangSmith 的分层导航、Phoenix 的会话列表与对话历史、Langfuse 的跨链路会话回放。

普通用户先看到目标、当前进展、需要处理的事项和结果。模型、推理强度、耗时和工具数量作为标签；参数、事件字段与 JSON 按需展开。

## Agent Matrix 建议布局

### 第一层：会话总览

- 左侧：项目、收藏、最近使用。
- 顶部：搜索；全部、运行中、待处理、已完成四个视图。失败原因作为待处理筛选项。
- 主体：宽行列表，默认按最近活动排序。每行两行正文，首行是会话标题，次行是最新进展。
- 每行辅助字段：状态、项目、最近一轮模型与推理强度、更新时间、回合数。
- 顶部独立「待处理」区域列出等待确认、等待回复、需要检查的失败；点击定位具体回合和节点。
- 少量会话时允许卡片视图；默认宽行列表适合会话增多后的扫读。

以下是示例内容，均为原型设计，不是实际运行状态：

```text
会话                                    当前进展                  状态
梳理 Agent Matrix 架构                  已读取说明，正在查询资料  运行中
核对前端依赖                             需要确认访问官方文档      等待确认
检查本地 Runtime 页面                    首次超时，重试成功        本轮完成
```

### 第二层：会话详情

- 顶部摘要：原始目标、最新进展、已产生的结果、待处理事项。
- 摘要下展示最近一轮模型、推理强度、累计 token、回合数。若不同回合换过模型，标记「使用过多个模型」，每轮显示各自配置。
- 中间按时间排列用户输入与回合摘要。每轮默认显示：用户要求、Agent 执行摘要、结果、状态。
- 每轮提供「查看执行链路」。展开后才显示当前 Runtime 拓扑。
- 切换会话后保留各自的选中回合、详情节点、筛选条件和滚动位置。

### 第三、四层：复用当前链路与节点卡片

每轮独立展示：输入 → 上下文与指令 → 模型循环 → 权限、Hook 与能力调用 → 返回结果。

节点卡片保持已确认的规则：

1. 执行摘要与状态。
2. 调用类型、服务名称、耗时、结果概括。
3. 手动展开输入参数与结果。
4. 深入关联事件与原始 JSON。

3D 拓扑作为选中回合的可选视图。动效用于正在执行的连线、等待确认和失败定位；多会话列表保持稳定、清楚。

## 状态与数据规则

- 会话与回合状态分别记录。「本轮完成」表示等待后续用户输入，不能因此把整个会话自动归档。
- 等待确认、等待用户回复、执行失败分别有明确文字标签，颜色仅辅助识别。
- 一次调用失败后重试成功，应显示「已恢复 · 1 次重试」；最终失败才进入需要处理区域。
- 连接中断时显示「遥测已断开 / 最后更新于…」，不能仅按长时间没有事件判定模型失败或卡死。
- 原型数据、真实数据、字段缺失均明确标记；未知模型、推理强度、费用显示「未采集」，不要填充默认值。
- sessionId 关联多轮，turnId 关联当前回合，callId 关联工具前后事件；子 Agent 另外保留父级关系。
- 会话总览使用聚合摘要，不同时加载和渲染每个会话的完整事件与拓扑。
- 用户阅读列表时，新事件更新内容与未读提示，避免自动重排导致行跳动；切回总览或主动刷新排序。
- 待处理标签来自实际审批或执行状态；没有执行能力的监测原型仅提供定位和查看。

## 下一版原型范围

新增多会话总览及会话摘要页面，复用当前单轮链路和详情组件。准备多会话、多回合 Mock：运行、等待确认、本轮完成、失败后恢复、最终失败、遥测断开。验证内容搜索、状态筛选、会话切换、回合选择和详情展开。

验收标准：用户能从总览读出「哪个会话、在干什么、是否需要我操作」，进入后能追溯某轮的输入、执行摘要、模型配置和具体调用。
