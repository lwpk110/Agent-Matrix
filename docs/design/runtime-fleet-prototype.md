# 本地多会话原型

## 页面层级

桌面从左到右采用「本地会话 → 当前会话运行阶段 → 运行详情」。运行阶段属于选中会话，不能作为全局导航；会话筛选与阶段选择分别操作不同层级。

会话列表提供搜索、全部／运行中／待处理筛选与历史分组。运行详情沿用共享 Runtime 拓扑、资源卡及节点详情。资源摘要采用 Token、上下文、记忆、能力四卡；提示词监控保留独立入口。

## 会话切换的一致性

列表与详情使用同一组原型数据。选中会话决定 Agent 品牌、模型、回合、状态和轨迹。状态覆盖运行中、等待权限、工具最终失败和回合完成；网关离线不等同于工具失败。

事件、调用、模型请求的标识在各会话之间隔离，内部关联保持有效。列表 Token 与资源概览来自相同的模型用量回执，没有回执时显示未知。

回放只推进当前轨迹的可见范围。节点详情、工具结果、累计用量与最终回答均应限制在已播放事件内，不能提前展示后续结果。切换会话时停止上一会话的回放和悬浮预览，避免旧调用筛选影响新会话。

输入草稿及演示提交按会话保存。回放操作不提交草稿；演示提交只替换当前会话的模拟输入，不执行真实任务。

## 本轮范围

本地会话清单仍是模拟原型。真实 Codex、Claude Code 页面继续消费各自采集数据；此原型不新增真实会话 API、后端采集或 3D 多会话视图。

正式接入时应复用相同的列表与详情层级，并遵循 [多会话调研](multi-session-research.md) 中的会话／回合区别、缺失字段、断线状态和事件关联规则。
