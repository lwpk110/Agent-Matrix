# Agent 资源信息组织：产品调研与原型决策

调研日期：2026-10-18。范围：当前选中回合的 token、上下文、记忆与能力展示。延续多会话方案中的“会话 → 回合 → Runtime → 事件”，这里不把多个会话的上下文或记忆混加。

## 实际阅读的官方资料

| 产品 / 来源 | 观察到的设计 | 本原型采用的思路 |
| --- | --- | --- |
| [Langfuse — Model Usage & Cost Tracking](https://langfuse.com/docs/observability/features/token-and-cost-tracking) | 区分输入、输出、缓存用量；提供商上报与 tokenizer/价格推算来源不同。缓存等包含式统计需要避免重复计入。缺少价格就无法可靠计算成本。 | 累计总量 = 输入 + 输出；缓存是输入子集。仅收到模拟用量回执后更新；不根据字符、粒子或计时器假装实时增长。费用与独立推理 token 缺失时显示“未提供”。 |
| [Claude Code — Explore the context window](https://code.claude.com/docs/en/context-window) | 交互式上下文组成展示，区分指令、记忆、Skill、MCP、消息、文件和工具输出，展示按需读取、子代理隔离及压缩过程。页面明确 token 数是代表性示例。 | 展示最近一次请求的上下文组成和窗口占用，与累计 token 消耗分开。能力目录、指南全文、执行结果是不同层级。分类与容量在本原型明确标注为估算示例，不宣称复现 Claude 或 Codex 的内部实现。 |
| [Letta — Memory](https://docs.letta.com/agent-sdk/memory/) | 持久记忆可以跨会话存在；部分文件始终带入，其他文件按需读取；共享作用域、版本化更新与后台整理是独立能力。 | 区分“已保存”“本轮已读”“已经带入最近请求”；显示用户/项目作用域、读取方式、来源和更新时间。保存不等于始终占上下文；历史压缩也不等于长期记忆写入。 |

以上为设计研究，不是本项目已接入相应服务的声明。不同 runtime 的加载机制、上下文上限、缓存与计费规则不能互相套用。

## 信息架构

默认四张摘要卡，单次只展开一个资源面板，避免增加一整屏指标墙：

1. **Token 用量**：累计已返回用量、输入/输出、缓存子集、逐次请求组成、最近回执。待统计请求明确等待，不显示虚假的每秒速度或费用。
2. **当前上下文**：最近一次请求快照、占用/窗口、分类组成、余量和压缩状态。分类为指令与约束、用户消息、工具/MCP 定义、已读记忆、已加载 Skill、历史与工具结果。
3. **记忆**：用户偏好始终带入；项目架构备忘按需读取；发布约定保存在库中但本轮未读。来源使用 `memory://demo/`，没有读写真实工作区文件。
4. **能力与控制**：Skill 指南、MCP 连接、本地工具、Hook 生命周期、权限门禁分开解释。目录数量与实际加载/执行数分开，并可进入现有节点详情。

披露顺序：摘要卡 → 人能读懂的组成与来源 → 折叠事件依据 → 按需展开输入输出与原始 JSON。

## 数据与交互边界

- `/codex` 仍为完整模拟原型，不是实际 provider 的实时遥测。本次新增 3 条虚构记忆、记忆发现/读取事件、每次模型请求的分类快照。
- 累计输入 11,930、输出 915、其中缓存输入 9,000，总计 12,845；最新请求上下文只有 3,540。数值展示两种不同口径，不相加。
- 上下文分类与 32,768 窗口为固定演示估算；自定义输入只替换模拟提示词，不触发真实 tokenizer、模型或记忆存取。
- 资源投影仅使用回放已到达的事件；未出现的用量、记忆目录和能力目录显示未知。按 round ID 去重用量回执，避免重复统计。
- 项目记忆在第 2 次请求之后被读取，直到第 3 次请求才带入；这两个状态分别显示。本轮没有记忆写入、历史压缩或子代理执行。
- 原始事件仍可检查，模拟事件是产品层 schema，不宣称为 Codex wire protocol。

## 后续真实接入

由适配器对齐 provider usage 字段与范围；输入是否包含缓存、输出是否包含 reasoning 都需要显式约定。上下文分类应注明来源（真实 tokenizer/估算/不可观测），缺少分类不能按比例造数。记忆需真实读取/注入/写入事件与作用域，不能从文件存在推断已加载。能力发现、MCP 连接状态和工具调用分别建模。

实时 token 是回执驱动的累计值；若 provider 不上报增量用量，在生成中保留最近已知值并显示等待。服务断连需另外展示数据新鲜度，不能推断 Agent 已停止。
